# Karya — CWI Studio's build of Plane

Karya (कार्य, "work") is [Plane](https://github.com/makeplane/plane) (AGPL-3.0) rebranded and run by CWI Studio as hosted
workspaces on subscription. Live at **https://karya.cwistudio.in**. This folder holds everything that is ours; the rest of
the tree is upstream.

## Branches and remotes

| | |
|---|---|
| `upstream` | `https://github.com/makeplane/plane` — never pushed to |
| `origin` | `https://github.com/aniket328/karya` — our fork (AGPL: the source users are offered) |
| `karya` | our default branch = an upstream release tag + our commits |

Base today: **v1.4.2**.

## What we change, and how it stays mergeable

| Change | Where | Merge cost |
|---|---|---|
| Name, copy, links (`Plane` → `Karya`, plane.so → CWI) | generated by `karya/rebrand.py` — never hand-edited | none: take upstream, re-run the script |
| Logo, favicons, OG image, email logos | `karya/brand/build_assets.mjs` writes over upstream file names | none: re-run the script |
| Logo components | `packages/propel/src/icons/brand/plane-logo.tsx`, `plane-lockup.tsx` (export names kept) | rare conflict, keep ours |
| Coral theme | `packages/tailwind-config/karya-theme.css` + one `@import` in `index.css` | one line |
| Upgrade → mail CWI sales | `apps/api/plane/karya/` (new), one include in `apps/api/plane/app/urls/__init__.py`, `apps/web/core/services/karya.service.ts` (new), `handleRedirection` in `apps/web/core/components/workspace/billing/comparison/plan-detail.tsx` | small |

Rules: hand-made changes carry a `Karya` comment; never rename upstream identifiers; keep every upstream
copyright header and `LICENSE.txt` (AGPL-3.0). Plane's name and logo are their trademark and must not appear in the UI.

Deliberately **not** rebranded: `intake@plane.so` (a backend identity the server compares against), `X-Plane-*` webhook
headers (integration contract), state/chart colours (they carry meaning), code comments, tests.

## Taking an upstream release

```bash
git fetch upstream --tags
git checkout karya && git merge vX.Y.Z           # conflicts in rebranded text: take upstream ("theirs"), our script redoes them
python3 karya/rebrand.py                         # re-apply name/links
node karya/brand/build_assets.mjs                # re-apply images (needs playwright + Chrome)
python3 karya/rebrand.py --check                 # must print "would change 0 files"
git commit -am "karya: rebrand vX.Y.Z"
grep -rnE "\bPlane\b" apps packages --include='*.tsx' | grep -vE ':\s*(//|\*)|Plane Software|import '   # new strings the script missed
```

Then build and deploy: `karya/deploy/README.md`.

## Pushing our own features upstream

Generic fixes (not branding, not CWI-specific) go to Plane as PRs from a branch cut from the **upstream** tag, never
from `karya`, so no rebrand noise leaks into the PR.

## Commercial behaviour

No self-serve signup on our instance (instance setting). CWI creates a workspace per client. The billing page keeps
Plane's plan tiers; **Upgrade** POSTs `/api/workspaces/<slug>/karya/upgrade-request/`, which mails
`KARYA_SALES_EMAIL` (default `aniket@cwistudio.in`) through the instance SMTP, reply-to the requester, at most once per
workspace+plan per 10 minutes. Falls back to a `mailto:` link. A payment gateway replaces this later.

## AGPL-3.0 obligations (§13)

Users interacting with Karya over the network must be offered the corresponding source of the version they use:
`https://github.com/aniket328/karya` (linked from the app and the emails). Keep it public and in sync with what is deployed.
